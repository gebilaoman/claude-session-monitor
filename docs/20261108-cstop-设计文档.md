# cstop — Claude Code 会话监控工具 设计文档

- 日期: 2026-11-08
- 状态: 待评审。评审通过后按里程碑实现。
- 项目位置: `~/Documents/work/gebilaozhongyi/claude-session-monitor/`,代码在 `code/`。

## 1. 背景与目标

Claude Code 会话在本机以两类形态存在:

1. 运行中的进程。每个进程占用内存。目前只能用 `ps` 手工查看。
2. 磁盘上的会话记录。位置为 `~/.claude/projects/<项目路径slug>/<会话id>.jsonl`。目前只能用 `find`/`du` 手工统计。

目标: 做一个终端 TUI 工具,实时显示这两类数据,外加会话活动摘要与阈值提示。

非目标:

- 不做跨机器聚合(只在装了它的机器上看本机)。
- 不做后台常驻告警(告警只在工具打开时的界面内呈现)。
- 不做云端同步、不做多用户。

## 2. 已确认需求

来自 2026-11-08 与用户的需求确认:

1. 跨操作系统: 同一工具在 macOS / Linux / Windows 各自运行,各自监控本机。
2. 监控内容,四项全要:
   - 运行中会话 + 内存
   - 磁盘占用(历史会话文件)
   - 阈值告警(仅工具打开时,界面内提示)
   - 会话活动(活跃会话最近在做什么)
3. 呈现形式: 终端 TUI。htop 风格。一条命令启动,全屏刷新。
4. 用户不参与编码。学习曲线不作为选型约束。
5. 自动更新: 工具检测 GitHub Releases 新版本。确认后自动下载并替换二进制。检测在启动时后台执行,另提供 `cstop update` 手动入口。

## 3. 技术选型

Go + Bubble Tea + gopsutil。

| 选项 | 结论 | 理由 |
|---|---|---|
| Go + Bubble Tea | 采用 | 单静态二进制,三系统交叉编译,分发零依赖;gopsutil 一套代码覆盖三系统进程/内存采集;TUI 生态成熟 |
| Rust + ratatui | 否 | 能力等价,开发与调试迭代更慢,无对应收益 |
| Node.js + Ink | 否 | 监控工具自身要常驻几十 MB 的 node 进程;分发依赖运行时 |

- Go 版本: 1.23+。
- 第三方依赖四个: bubbletea、lipgloss(界面)、gopsutil(采集)、go-selfupdate(自动更新)。
- go-selfupdate 覆盖更新全流程: 查 GitHub Releases、semver 比较、按 GOOS/GOARCH 匹配产物、校验 checksums、三平台原子替换二进制。自写代码只剩装配层。
- 工具名 cstop(claude session top),目录名 claude-session-monitor。2026-11-08 查名: ccmon、cctop、ctop 在同类工具中已有重名;cstop 无冲突。

## 4. 总体架构

单向依赖: `main → ui → collect`,`main → update`。config 由 main 装配后注入: 阈值给 ui(决定高亮),刷新间隔给采集节奏。ui 不依赖 update 包;启动检测结果由 main 异步取得后注入。

- collect(采集): 产出快照数据。不关心界面。
- ui(呈现): 消费快照,渲染 TUI。
- config(配置): 阈值与刷新参数。
- update(更新): 检测新版本,下载并替换二进制。见 5.5。

数据流: 定时 tick → `collect.Snapshot()` → 渲染。进程数据每 tick 采集。磁盘扫描开销大,单独低频刷新,结果缓存到下一次。

## 5. 模块设计

### 5.1 internal/collect — 采集

职责: 输出一份完整的机器快照。

```go
type Snapshot struct {
    Procs     []Proc         // 运行中的 Claude Code 会话进程
    Projects  []ProjectDisk  // 磁盘上的项目占用
    TotalDisk int64          // projects 目录总字节
    Errors    []string       // 采集中的降级说明
}

type Proc struct {
    PID             int
    RSS             int64         // 字节
    StartedAt       time.Time
    ProjectDir      string        // 进程 cwd;取不到为 ""
    SessionID       string        // cmdline 中 --resume 的 id;没有为 ""
    LatestActivity  string        // 关联会话文件的最近动作摘要,≤40 字符
}

type ProjectDisk struct {
    Name       string  // 项目目录名(项目路径的 slug)
    Sessions   int     // 主会话 jsonl 数(不含 subagents)
    Bytes      int64
    LastActive time.Time
}
```

进程识别规则:

- cmdline 中含可执行名 `claude`(Windows 为 `claude.exe`)。
- 排除两类: 路径含 `Claude.app`(macOS 桌面应用助手进程);本工具自身 PID。
- 采集字段: PID、RSS、启动时间、完整 cmdline、cwd。

会话文件扫描:

- 根目录 `~/.claude/projects`。三系统同构,用 `os.UserHomeDir()` 取 home。
- 每个一级目录 = 一个项目。目录名是项目路径的 slug,`/` 与 `\` 都替换为 `-`。
- 其下 `*.jsonl` = 主会话记录。`<uuid>/subagents/*.jsonl` = 子代理记录,计入项目字节数,不计入主会话数。
- 每项目统计: 主会话数、占用、最近 mtime。
- 占用按磁盘块字节统计(文件与目录 inode,与 `du` 口径一致);Windows 用文件大小。
- 2026-11-08 修正: 磁盘统计范围扩为 `~/.claude` 全目录。`projects` 下按项目,其余一级目录与文件(plugins、file-history、skills 等)各成一行;此前只统计 projects,少计约 40%。

会话活动:

- 对"活跃项目"(存在对应运行中进程的项目),取 mtime 最新的主会话 jsonl。同项目有多个进程时,活动列对每个进程显示同一条(项目级最新)。
- 读文件末尾 64KB,取最后一条可解析的 JSON 行。
- 解析字段: `type`、`message.role`、`timestamp`、content 数组中的 `tool_use.name`。
- 生成摘要,例: `Bash · 12:03:41`、`回复 · 12:05:02`。超长截断。
- 单行解析失败显示 `?`,不让坏行影响整体。

### 5.2 internal/config — 配置

- 位置: Linux/macOS 用 `~/.config/cstop/config.toml`;Windows 用 `%APPDATA%\cstop\config.toml`。
- 文件不存在时用内置默认值。`--init-config` 可生成。
- 顶层的刷新间隔与阈值:

| 键 | 默认 | 含义 |
|---|---|---|
| refresh_procs_sec | 2 | 进程与活动刷新间隔(秒) |
| refresh_disk_sec | 60 | 磁盘扫描间隔(秒) |
| warn_session_rss_mb | 400 | 单会话内存告警线。2026-11-08 实测单会话 103~310MB |
| warn_total_rss_mb | 1500 | 全部会话内存合计告警线 |
| warn_disk_project_mb | 500 | 单项目磁盘告警线。实测最大项目 477MB |
| warn_disk_total_mb | 2000 | ~/.claude 总量告警线。实测 1.7GB(projects 1.0GB + plugins/file-history 等 0.7GB) |
| warn_session_count | 6 | 运行会话数告警线 |
| update_check_on_start | true | 启动时后台检测新版本。关闭后仅 `cstop update` 手动检测 |

默认值取自 2026-11-08 本机实测。都可以在 config 改。

### 5.3 internal/ui — TUI

Bubble Tea + lipgloss。两个 tab + 顶部状态栏 + 底部键位栏。

```
┌ cstop ─────────────── 会话 4 · 内存合计 674MB ⚠ ──────────────────┐
│ [1] 运行中   [2] 磁盘                  (2s 刷新 · 12:06:11)        │
├───────┬────────────────────┬────────┬──────────┬─────────────────┤
│ PID   │ 项目               │ 内存   │ 运行时长 │ 最近活动        │
├───────┼────────────────────┼────────┼──────────┼─────────────────┤
│ 1423  │ zelig              │ 310MB  │ 2d 6h    │ Bash · 12:05    │
│ 21721 │ tuanyixian         │ 103MB ⚠│ 1h       │ 回复 · 11:58    │
├───────┴────────────────────┴────────┴──────────┴─────────────────┤
│ q 退出 · 1/2 切换 tab · ↑↓ 滚动 · r 立即刷新 · Enter 详情        │
└───────────────────────────────────────────────────────────────────┘
```

- 项目显示名取 slug 末段(如 `-Users-...-work-zelig` 显示 `zelig`),完整路径在详情页。
- 磁盘 tab 列: 项目 | 会话数 | 占用 | 最近活动。`~/.claude` 全目录: projects 下按项目,其余一级目录/文件同表展示;按占用降序,非项目行会话数显示 `-`。阈值适用于每一行。底部合计行 = `~/.claude` 总占用。
- 超阈值表现: 行内数值超限标黄,超限 1.5 倍标红;状态栏汇总 ⚠。
- 详情页(Enter): 单个会话最近 20 行活动摘要,Esc 返回。
- 新版本提示: 检测到新版本时,状态栏追加「新版本 vX.Y.Z 可用,按 u 更新」。按 u 退出 TUI,在普通终端执行更新流程。无新版本不显示。

### 5.4 cmd/cstop/main.go

- flag: `--refresh`、`--config`、`--init-config`、`--dump`、`--version`。
- 子命令 `update`: 检测并安装最新版本,流程见 5.5。
- `--dump` 跳过 TUI,直接打印一份快照文本。给 M1 验数据和脚本化用。
- 版本号由构建注入: CI 用 ldflags 写入 git tag;本地构建为 `dev`。版本为 `dev` 时跳过更新检测。
- 装配 config → collect → ui,启动 Bubble Tea。启动时同时发起异步版本检测(见 5.5),结果注入 ui。

### 5.5 internal/update — 自动更新

职责: 检测新版本;下载并替换自身二进制。仅 main 调用。

两个入口:

- `Check(ctx)`: 查 GitHub 最新 Release,与注入版本比较。返回是否有新版与版本号。启动检测用。
- `Run(ctx)`: 检测 → 下载产物 → 校验 sha256 → 原子替换 → 打印结果。已是最新则打印提示并正常退出。`cstop update` 子命令用。

平台相关细节由 go-selfupdate 处理,含 Windows 运行中 exe 先改名挪开再替换。

更新源与产物约定(与 M4 发布流程对应):

| 项 | 约定 |
|---|---|
| 更新源 | GitHub Releases `gebilaoman/claude-session-monitor`(公共仓库,匿名可下载) |
| 产物名 | `cstop_<version>_<os>_<arch>.tar.gz`;Windows 用 `.zip` |
| 校验文件 | `checksums.txt`,每行 `<sha256>  <文件名>` |
| 版本号 | git tag,格式 `vX.Y.Z`(semver) |

- 启动检测在 main 装配时异步发起,3 秒超时,失败静默。结果注入 ui,由状态栏呈现(见 5.3)。
- 已知限制: 经包管理器(如 brew)安装时,`cstop update` 会替换包管理器管理的文件。此类安装请用包管理器更新。README 说明,工具内不做检测。

## 6. 错误处理

| 场景 | 行为 |
|---|---|
| `~/.claude/projects` 不存在 | 磁盘 tab 显示空态提示,不报错 |
| 进程 cwd 取不到(Windows 常见) | 项目列回退显示 `--resume` 的 id 或 `-`;活动列显示 `-` |
| jsonl 末行解析失败 | 活动列显示 `?` |
| 配置文件损坏 | 用默认值,状态栏提示一行 |
| gopsutil 枚举失败 | 显示上一份快照;连续失败 3 次在状态栏报错 |
| 启动版本检测失败或超时 | 静默,不影响 TUI |
| `cstop update` 网络失败 | 明确报错,退出码非 0 |
| 下载产物 sha256 校验失败 | 放弃安装,保留旧二进制,报错 |
| 二进制替换失败 | 保留旧二进制,报错;不产生半写状态 |

- 三平台: GitHub Actions matrix(darwin/linux/windows × amd64/arm64)构建;runner 上跑单测与 `cstop --dump`(不跑交互 TUI)。
- 验收清单: 三系统二进制可运行;四类数据(运行中/磁盘/活动/阈值)正确;空态与降级路径可见。
- 自动更新: CI 发布后自动下载产物并校验 checksum。手动验收: 从旧版本执行 `cstop update` 升级成功,三平台各验一次。
